LINEWORK NATIVE BRIDGE — KRITA 5.2.14
Public release: 0.1.2 (development reports retain their original version labels)

Linux build: KDE Neon x86_64, Qt 5.15.17, Python 3.12.
Windows build: official Krita 5.2.14 x64, Qt 5.15.7, LLVM-MinGW 18.1.8 UCRT,
Python 3.10. The bridge requires the matching application ABI. Do not substitute
other native DLLs or load it into another Krita version.

Official sources: https://github.com/KDE/krita/tree/v5.2.14
Revision: 31056c6b76a164069752fc9d5f655f9479aca246

Linux
Requires g++ C++17, official headers, compatible installed Krita libraries,
Qt 5 SDK, Boost and KF5 (I18n, CoreAddons, Config, WidgetsAddons, Completion,
GuiAddons, ItemModels). From this folder:
python3 build.py --krita-source /path/krita-5.2.14 --sdk-prefix /path/sdk/usr
The default SDK prefix is /usr. Output: liblinework_native.so.
Standalone vectorizer: python3 build_vectorize.py
Output: liblinework_vectorize.so. No Qt/OpenToonz application SDK is required.

Windows cross-build from Linux
Use LLVM-MinGW's 20240619 UCRT release (Clang 18.1.8):
https://github.com/mstorsjo/llvm-mingw/releases/tag/20240619
Use the official portable Krita 5.2.14 Windows archive:
https://download.kde.org/Attic/krita/5.2.14/krita-x64-5.2.14.zip
Fetch Windows Qt 5.15.7, Boost and KF5 SDK packages from KDE's public Krita
Windows package registry, not Linux headers. Package provenance is recorded
in docs/validation/windows-build.json. The SDK contains include/QtCore,
include/KF5 and include/boost. Krita's dependency management repository:
https://invent.kde.org/packaging/krita-deps-management/-/tree/krita/5.2

python3 build_windows.py --krita-source /path/krita-5.2.14 \
  --sdk-prefix /path/windows-sdk --krita-bin /path/krita-x64-5.2.14/bin \
  --toolchain /path/llvm-mingw-20240619-ucrt-ubuntu-20.04-x86_64

The script generates import libraries from the official application's DLL
exports; it never substitutes the SDK's runtime DLLs. Output:
linework_native.dll and linework_vectorize.dll. Krita already supplies libc++
and the UCRT runtime; system/Krita DLLs are not bundled with the plugin.
The generated OpenToonz tgeometry.h omits only Windows template export
instantiations placed before explicit specializations, which Clang rejects.
This private DLL does not expose those C++ templates. Mathematical code and
vendored originals are unchanged; the generated header is build-only.
Reinstall and restart Krita after rebuilding. Validate with isolated resources.

Architecture
Krita's Python API cannot replay a complete continuous sample sequence through
native presets. The bridge receives libkis objects through SIP, obtains the
image/node and view resources, and uses FreehandStrokeStrategy. One native
stroke contains all interpolated lines, preserving continuous brush spacing.
Official headers and exported Node::image/node, View::view, Resource::resource,
Shape::shape and KisShapeLayer::canvas are used. Explicit member-pointer
instantiation accesses private members without modifying class layouts.
The bridge is GUI-thread-only and depends on the exact Krita ABI.

Rendering uses an internal image without an extra document/view. A private
preset, local resource provider and empty selection preserve user settings.
The scratch image is reused. Barrier jobs copy preview appearance in a worker;
the GUI reads ready images without waiting for an open stroke. PNG compression
happens at commit. Closing the canvas releases the scratch image.

Tools
KoToolFactoryBase/KisToolPaint factories register in KoToolRegistry before the
first canvas. The KoToolManager action list is refreshed. Each tool provides
a QWidget to native Tool Options. Native layer models and indices are retained.

Editing
Confirmed KoShapes remain layer children. During dragging, only their render
registration is removed; preview replaces appearance. SVG and fingerprints
remain intact. A native stroke coordinates save/close so original appearance
is restored before projection reads. Python caches existing embedded images,
including reopened documents, without rerunning random presets on selection.

Affine transforms
Absolute matrix and normalized size are read, and an untransformed clone is
serialized to check for affine-only edits. Adoption preserves the top-level
KoShape and matrix, updates local ImageShape/KoPathShape content and compensates
for the transform. Native move/scale undo references remain valid. Sync waits
for input release and two stable matrix reads. Schema 6 stores independent
width profiles, transforms, signatures, handles and scalar controls.

Vectorization
linework_layer_snapshot color-converts a copied QImage, preserving source pixels.
The original OpenToonz Centerline core runs through ctypes.CDLL in a worker;
progress/cancellation use atomics, and a mutex protects file-local globals.
Original BSD sources/math and host patches: opentoonz/ and VECTORIZATION.txt.
Tests compare 16 fixtures against unpatched original sources using host adapters.
Run from repository root: python3 -m unittest discover -s tests -v

Protected writes
VectorLayer::addShapesFromSvg and Shape::remove execute image worker commands.
KisImage::waitForDone may normally process Qt events, letting timers query
KoShapes during mutation. linework_shape_write_begin/end hold an outer wait
through KisBusyWaitBroker::notifyWaitOnImageStarted/Ended, after draining prior
jobs. Nested waits do not reopen event feedback; workers finish before release.
Python uses finally, guarding imports, removals, metadata and projection.
Rendering/PNG preparation precedes mutation. Other plugins' timers are unchanged.

Independent diameter
linework_pressure_to_size uses KisCubicCurve's 256-entry interpolation table.
A private preset replaces Size sensors with a linear Perspective-channel
sensor; Pressure still carries original input. Edited samples use five values
versus legacy four. Diameter maximum: 2000 px. Pixel/Color Smudge validation
happens before SVG preparation. linework_paint_with_thickness has its own ABI
name so old bridges cannot silently accept the new argument layout.

Native smoothing
smoothing.h uses KisToolFreehandHelper, KisPaintingInformationBuilder and
KisSmoothingOptions directly. A KisStrokesFacade intercepts native freehand
jobs without painting into the user document. Eleven doubles per segment
copy line/cubic geometry and pressure into native_smoothing.py.
Filters, timers, tablet pressure curves and finishing are native. Zero-length
constant-pressure lines are dropped; closed cubics and stationary pressure
changes remain. Resources are private. cancelPaint stops native timers.
A nonpainting document stroke coordinates save/clone; its end signal finalizes
geometry before saving. Python timers and overlays check KisBusyWaitBroker,
including during native view destruction.

Compaction
After endPaint/take, native_smoothing.py calls curve_fit.compact_stroke for new
Brush strokes only. Python fits cubics with endpoint tangents and least squares;
pressure/diameter have scalar controls sharing the same parameter. De Casteljau
subdivision bounds chord error. Full interval control polygons, including
sensors, are validated. Corners above 60 degrees form boundaries. Sample/work
limits preserve originals. _live_points stays unchanged, avoiding cursor jumps.
Schema 6 stores the new cubics with the same preset and stroke ID.

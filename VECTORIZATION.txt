VECTORIZATION — THE OPENTOONZ CENTERLINE ALGORITHM PORTED TO KRITA

This integration reimplements/ports the same OpenToonz Centerline algorithm
inside Krita by compiling its original BSD-3-Clause sources with host adapters.
It replaced the pixel-thinning implementation in version 0.6.0.

Executed algorithm
1. tcenterlinepolygonizer.cpp: PixelEvaluator classifies the raster;
   extractBorders extracts outer/inner contours and removes small areas;
   reduceBorders reduces contours into polygons using the original criterion.
2. tcenterlineskeletonizer.cpp: skeletonize contracts oriented contours,
   including holes, through the original straight-skeleton geometric events.
   Node Z coordinates retain the calculated radius.
3. tcenterlineadjustments.cpp: organizeGraphs organizes junctions, sequences,
   cycles and points. junctionRecovery remains disabled, as in the original
   centerlineVectorize flow at this revision.
4. tcenterlinecolors.cpp: calculateSequenceColors and applyStrokeColors run
   in their original order. RGB/grayscale uses the closest-to-black style.
5. tcenterlinetostrokes.cpp: original SequenceSimplifier/SequenceConverter
   produce quadratic strokes, penalizing radius deviation through ellProd.

Original tgeometry.h, tutil.h, tcommon.h, tnztypes.h and tgeometry.cpp provide
geometry, tolerances and matrix inversion. compat supplies raster buffers,
TStroke control storage, a black/transparent palette and progress/cancellation,
without application Qt objects. Emitted radii are validated as nonnegative.

Exposed parameters
- Light background: max(R,G,B) < threshold * alpha / 255, the original RGB
  PixelEvaluator criterion. This uses maximum channel value, not weighted luma.
- Alpha: prepare grayscale = 255 - alpha, threshold = 256 - alphaThreshold.
  The same GR8 polygonizer then implements alpha >= alphaThreshold.
- Despeckling: m_despeckling, contour area in square pixels.
- Accuracy: m_penalty = 10 - accuracy, matching OpenToonz's parameter mapping.
- Maximum width: m_maxThickness = maximumWidth / 2. Width is positive;
  separate outline mode and filled regions are not Linework tools.
The panel defaults do not reproduce every OpenToonz UI preset. Compare cores
with identical input and parameters.

Exact degree elevation
Raster Y is flipped on input and returned to Krita orientation on output,
preserving the core's pixel-corner coordinates. Each quadratic (A,C,B) becomes
(A,A+2(C-A)/3,B+2(C-B)/3,B). This applies equally to X, Y and radius.
No refitting, median filter, RDP or smoothing follows the original core.
pressure_in/out initially store relative scalar controls for the width profile.
Schema 6 also supports diameter independent of recorded pressure and reads
older schemas. De Casteljau insertion subdivides the scalar profile too;
affine transforms and undo/redo preserve its controls.

Appearance and host integration
Preserve color/transparency samples the bitmap after geometry extraction.
Disabling it retains the original RGB core's black palette choice. Appearance
sampling and native Krita presets do not change detected geometry.
Linework/Krita render the result; OpenToonz's renderer is not used.
Pixel-identical output to the complete OpenToonz application is not claimed.
TLV colormaps, NAA preparation, TVectorImage regions/fills and the separate
outline technique are not implemented. Branches remain independent strokes.

Host patches without changed geometric calculations
Compiled copies in opentoonz/core differ only through:
- Deleting BorderList after the polygonizer empties it, avoiding preview leaks.
- Initializing RandomizedNode::m_number to zero. Its member/comparator are
  unused by this flow; initialization avoids consuming the host's global rand().
- An extra cancellation checkpoint in the timeline, followed by original cleanup.
Cancellation applies no partial result. A mutex serializes the core because
original adjustment routines use file-local globals. An unused colormap
histogram has a std::map adapter with equivalent ordered-key operations;
colormaps are not exposed.

Correspondence validation
tests/test_opentoonz.py compiles the five unpatched original routines and
original math with the same host types. Its separate driver calls the original
flow in the same order; it does not use the patched core or old thinning code.
Sixteen cases cover capsules, holes, junctions, crossings, variable width,
corners, diagonal ambiguity, canvas edges, despeckling, thickness limits,
threshold equality, three penalties and white alpha. Quadratic X/Y/radius
controls match exactly. Source hashes and the three declared patches are checked.
Quadratic/cubic equality is tested at 101 parameters per segment, including
width, serialization, insertion and affine transforms. This compares the core,
not the full OpenToonz application. See docs/validation/opentoonz-reference.json.

Execution
The native vectorizer runs through ctypes.CDLL in a QThread, releasing the GIL.
The worker prepares curves/preview outlines; zoom uses cached geometry.
Document and brush objects are accessed only on Krita's main thread.
Confirming creates the new layer and preserves the active bitmap source.
Progress, cancellation and old-ABI restart diagnostics are provided.

Linux build: python3 linework/native/build_vectorize.py
Tests: python3 -m unittest discover -s tests -v
Requires a C++17 compiler and its standard library, not Qt or OpenToonz SDKs.
The Krita bridge is separate; see linework/native/BUILD.txt for platform builds.
The Windows build uses a generated tgeometry.h that omits only Windows C++
template export instantiations before their specializations, which Clang rejects.
Original mathematical definitions and vendored files remain unchanged; these
private C++ templates do not need DLL exports. This is a build adaptation,
separate from the three host patches to the compiled algorithm sources.
Limits: 32 million pixels, 10,000 strokes and 20,000 anchors per stroke.
